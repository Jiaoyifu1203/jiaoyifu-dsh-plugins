# jiaoyifu UI 设计工作台

把一次视觉产出当成「先风格决策、再高保真实现、最后过门禁」的三段流水线。HTML 是工具而非默认媒介——先判断交付形态（网页/原型/海报/封面/演示），再选实现路径。

## 0. 前置判断（省 token，别一上来就写代码）

| 信号 | 动作 |
|---|---|
| 需求只说「做个 XX」没给风格 | 进入风格顾问：给 3 个方向（关键词+参考图描述+适用场景），用户选后再动手 |
| 是品牌/活动物料（海报、封面） | 先调用 jiaoyifu-style-detector 拆参考图（若有），走「先图后字」架构 |
| 是网页/产品界面 | 先定风格与设计 tokens（色板/字体/间距/圆角），再写 HTML/CSS |
| 是数据/汇报 | 走 jiaoyifu-data 或 jiaoyifu-presentation-architect，不要用本技能硬做 |

## 1. 风格决策（10 秒给方向）

内置风格库（给出关键词即可展开实现）：

| 风格 | 关键词 | 适合 |
|---|---|---|
| 瑞士网格 | 栅格、大字、留白、Helvetica 感 | 官网、B2B、专业感 |
| 极简留白 | 白、少、克制、MUJI | 品牌、个人页、高端感 |
| 巨字冲击 | 超大字号、对比、街头 | 海报、封面、活动 |
| 玻璃拟态 | 毛玻璃、渐变、通透 | 仪表盘、AI 产品 |
| 霓虹暗色 | 深底、霓虹、赛博 | 开发者工具、夜间场景 |
| 新中式 | 留白、宋体、印章、意象 | 节气、文化、内容号 |
| 编辑排版风 | 杂志网格、衬线体、大图 | 内容站、知识产品 |
| 数据大屏 | 深色、卡片、图表 | 可视化、汇报 |

风格审核可调用角色视角技能：原研哉（做减法）、佐藤可士和（icon化）、Paula Scher（巨字）、Herbert Bayer（系统一致）。

## 2. 高保真实现（HTML 优先）

- 单文件 HTML：内联 CSS，自包含，可直接双击打开 / 截图交付。
- 先定 tokens：`--color-* / --font-* / --space-* / --radius-*`，再写组件，拒绝随手取色。
- 移动端 375 宽基准，桌面 1440 宽基准；海报默认 9:16 或 3:4 竖版。
- 中文排版铁律：行高 1.7-1.9，段宽 ≤ 34 字，标题字重 700+，正文不加粗。
- 避免 AI 味：拒绝千篇一律的紫蓝渐变卡片 + emoji 图标堆砌；用真实内容填充，不写 Lorem。

## 3. 美感门禁（交付前自检，10 条二元标准）

逐条打勾，有一条不过就回去改，不要带病交付：

1. 第一眼有明确的视觉焦点（不是所有元素一样大）
2. 色板 ≤ 3 主色 + 1 强调色，全部来自 tokens
3. 留白足够，元素不贴边不拥挤
4. 字体层级 ≤ 4 级，标题与正文对比清晰
5. 网格对齐，元素边缘落在同一套栅格上
6. 图片/图形与文字有遮挡关系，不是并排贴图
7. 没有 AI 味：无多余渐变卡片、无 emoji 图标滥用、无模板腔
8. 中文文案可读：字号 ≥ 14px（正文）、对比度达标
9. 可交付：单文件打开即所见，无外部依赖
10. 符合场景：海报是竖版、封面有标题钩子、网页有明确行动按钮

## 4. 交付与评审

- 交付时说明：实现路径（HTML 单文件 / 截图 / 原型）、在哪打开、改哪个值能换风格。
- 用户要「再调一下」时：先问改什么（风格/文案/布局/颜色），一次只改一个维度。
- 设计评审场景：先描述 3 个优点 + 3 个风险，再给具体修改建议，不空谈感觉。
